# 模型设置是数据目录里的一份文件，界面改完立刻生效

## 背景

[ADR 0010](0010-model-endpoints-are-the-users-choice.md) 把模型端点交给使用者自决，落地方式是
**环境变量**（`.env.local`）。对命令行没问题是，但把错题本打包成桌面程序（Tauri）之后，
用户**没有 shell 去 export 环境变量**——「文件在哪、变量叫什么」成了使用门槛。

所以需要一个界面。它必须先回答两个问题：**设置存哪**、**改了什么时候生效**。

## 决定

1. **存 `<数据目录>/settings.json`**（[ADR 0008](0008-runtime-files-live-in-the-user-data-dir.md) 那个目录）。
   和用户的数据放一起，**备份数据就等于备份设置**；它天然不在仓库里（[ADR 0001](0001-file-backed-data-with-write-service.md)）。
   权限 `0600`，先写临时文件再原子替换。
2. **三层来源，逐字段回落**：设置文件 ＞ 环境变量 ＞ 预设默认。
   界面把每一项「来自哪一层」标出来（`source`）。
   整份覆盖会让界面上没设过的那一项凭空盖掉 `.env.local`；反过来"环境变量永远赢"会让
   界面上改了却不生效——对单用户桌面程序，后者更常见也更难查。
3. **改完立刻生效**：服务每次模型调用前重读那份文件（`settings.role_config`），
   保存成功后重建那几份模型配置（`Api.reload_model_configs`）。
   Tauri 里「重启 sidecar」是额外的一整套生命周期，而读一个 JSON 的成本可以忽略。
4. **密钥不回显**：`GET` 只给 `key_set` 与末四位；`PUT` 里省略或空串＝**不改动这一项**，
   显式 `null` 才清掉。第二条是判据（有测试钉着）——「加载一次再保存一次把密钥抹掉」
   是这类设置页最常见的**静默数据丢失**。
5. **写盘前先校验**：候选设置跑一遍四个角色（`extract`／`segmenter`／`judge`／`brief`）
   的解析，装不起来就 400、**一个字节不写**。「坏配置起不来」在写入口也要成立。
6. **设置文件坏了不熔断、但绝不静默**：读不出来时服务照常跑（读题卡不该被一份坏设置拖死），
   模型配置退回环境变量／预设，而**每一个响应**的 `warnings[]` 里都带上原因。
   熔断与静默之间还有第三条路：照常服务，但每一次都说明配置不是那份文件给的。

## 后果

- 密钥多了一个落点（数据目录里的文件）。它与 `.env.local` 同级的纪律：`0600`、
  **不进任何响应、不进日志**。
- 界面成了模型配置的**主入口**，环境变量退成第二层（无头／CI 仍然可用）。
- 设置改了不必重启，代价是每次模型调用多一次小文件读取。
- 换模型要重跑验收这条纪律**不变**（[ADR 0010](0010-model-endpoints-are-the-users-choice.md)）：
  界面让"换"变容易了，所以「不过考不许上岗」更需要被记住。

## 本版不做

- 设置页的「测试连接」（真发一次模型请求）：它要联网、要花钱，必须是显式动作，
  留到界面那一版。本版两个端点都不发起模型调用。
