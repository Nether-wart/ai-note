# 错题数据以文件为源，由一个独立写入服务维护派生索引

## 背景与决定

错题数据（题目、判定、重做历史）以「一题一文件」的形式存放在仓库内的数据目录中，文件即数据库，git 充当版本历史与备份。所有写入——录入、判定回写、状态变更——只经过一个独立的本地写入服务，它同时维护一份供界面运行时读取的派生索引 JSON。Docusaurus 只负责渲染与打印排版，**数据变更永不触发 Docusaurus 重建**，只有主题与代码变更才重建。

Docusaurus 是构建期的静态站点生成器，本身没有服务器、写路径与数据库；而本系统的核心是运行时的（上传、AI 判定回写、重做状态、间隔计时、动态选题）。把写入放在构建管线里，会让"录入一道题"变成"等一次完整构建"，这在手机上录题时是不可接受的摩擦。

## 考虑过的替代方案

- **单一 SQLite，构建时导出静态 JSON**：查询规整，但需要 schema 与迁移，且备份、手改、版本历史都要自建。文件方案把这三件事直接交给 git 和文本编辑器。
- **全部写进 Docusaurus 内容目录，写完重新 build**：最忠于"魔改 Docusaurus"，但每次录入与每次重做都要等几十秒。
- **放弃 Docusaurus，用 Vite/Next 自建**：运行时能力天然具备，但放弃 MDX 写作流、主题与插件生态，打印版式要从头搭。

## 后果

- 界面上的数据读取路径不经过构建，写入延迟只取决于写入服务本身。
- 索引是派生数据，任何时刻都可以从题目文件重建；因此索引损坏不是数据丢失。
- 数据可脱离应用被阅读、编辑与 diff，长期可迁移性由文件格式保证。
