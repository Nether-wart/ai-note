# 重做纸印擦除手写后的原题照片

## 背景

ADR 0004 选了「重做纸印题面转录」。它的代价在写下时就知道了：**转错一个符号就等于换了一道题**，而做题的人看不出这一点。那是一个用「审核必须逐字对照」来兜的风险。

改选的方案两全：重做纸仍印**原题照片**——题意绝不改变，因为它就是原件——但先把手写字迹擦除。前提是擦除足够可靠，而"文档手写去除"恰好是一个有人认真做过的方向（见下）。

## 决定

1. **重做纸印擦除手写后的题面照片；复习纸印未擦除的照片**（含你的原解与订正）。两张纸都是原件，区别只在擦没擦。
2. 擦除**分级**，依据是泄露的危害不对称：
   - **必须擦净：订正与批改**——它含正确答案，泄露它等于把答案印在重做纸上。订正常用红笔，**颜色可分，传统图像方法（颜色掩膜 + 修补）就够，不需要模型**。
   - **尽力擦净：黑笔原解**——它泄露的是你自己的错解，危害远小于泄露答案（看到自己的错解 ≠ 看到正确答案）。黑笔与印刷体同色，颜色分不开，需要分割模型。
3. 擦除只作用于**手写掩膜**，而掩膜是可见、可审的产物：**擦除是半自动的**——机器给初值（彩笔靠颜色，黑笔靠模型框），你在审核里直接增删掩膜。这是决定 2 与决定 4 的实测逼出来的结论：擦不干净会泄露答案、擦过头会改变题意，两侧都危险，而机器两侧都不稳；审核本来就要看这道题的图，顺势看一眼掩膜只多花几秒。全自动只有一条路（自训分割模型），见文末。
4. **验收方式**：把擦除后的图交给视觉模型，问它"这上面还有手写痕迹吗、写的是什么"。若它能读出原答或订正，擦除就算失败。这是视觉探针那套思路的复用。

## 后果

- ADR 0004 作废：题面转录退回它原来的位置——检索与打标用，不再承担印刷职责。
- 审核的重心从"逐字校对转录"改为"看擦除结果"：手写除净了吗、印刷体被伤到了吗、掩膜对不对。
- 引入一个新的不确定性：擦除效果本身。它必须像别的模型一样**接受验收**（擦除探针），而且**两侧都是危险方向**——擦不干净会泄露答案，擦过头会改变题意。这正是"掩膜可审 + 人工确认"必需的原因。
- 若能找到可直接使用的开源权重，这条路会比自训便宜得多；找不到则自训需要 GPU，而本机没有 GPU 驱动。

## 考虑过的替代方案

- **印转录文字**（ADR 0004）：不泄露、省墨、版面齐，但转录错误会静默改变题意。
- **印未擦除的照片**：立刻可用，但会把订正（连同答案）一起印出来。
- **只擦彩笔、接受黑笔残留**：可以作为第一版落地（见决定 2 的分级），但它不是终态。

## 已知的现成轮子

- [DocUnfold](https://github.com/CXH-Research/DocUnfold)（IEEE TCE 2025）——"Handwriting Contamination Removal in Documents"，含真实大规模数据集 [HW5K](https://huggingface.co/datasets/lkljty/HW5K)。**核实结果：仓库里只有网络定义（`models/DocUnfold.py`）、训练与推理脚本、配置文件，没有发布预训练权重**——即它是"架构 + 数据集"，不是能直接用的轮子；要用就得自己训，而本机没有 GPU 驱动。
- [HWR200](https://huggingface.co/datasets/AntiplagiatCompany/HWR200)——手写去除数据集。
- 场景文字擦除一线（SCUT-EnsText 等）：任务不同（照片里的招牌文字），但技术可迁移。

## 实测后的修订（同日，跑完第一版之后）

三处决定被实测改了：

**决定 4 作废重写：视觉探针不能当擦除的闸门。** 同一张图连问三次的对照实验结果：

| | 泄漏探针（"还有手写吗"） | 损伤探针（"印刷体完整吗"） |
|---|---|---|
| 擦除客观良性的那张（只擦了 357px、无一行墨迹损失 >30%） | `有手写：60` / `没有` / `没有` → 1/3 误报 | `完整` / `有白线涂抹` / `完整` → 1/3 误报 |
| 擦除客观有伤的那张（某行墨迹 20→8px，损失 60%） | 三次都指到受损处 | `完整` ×3 → **3/3 漏报** |

它能读出"这里有手写"，但"还剩没剩""坏没坏"要求像素级比对，它在编。**闸门改为确定性统计 + 人眼**：残留彩笔像素（应 0）、擦除后新出现的深色像素（应 0，这一条抓到过一个边缘填补的真 bug）、疑咬印刷体（应 0）、实擦面积占比（查擦过头）。模型的判词降级为**线索**，不是判据。

误报已被确证一次：探针在擦除良性的那张图上坚称"手写填写了数字 50 / 被白线涂抹无法辨认"，而原卷上那个 `50` **是人手确认过的印刷体**。它盯着的正是"印刷体数字坐在填空式位置上"的地方——这暴露了探针最坏的一类误报，也暴露了本任务最难的一类题：

> **填空题（以及学生圈选选项的选择题）是擦除与探针共同的最难情形。** 学生的作答落在空白处，与印刷体**同色、同行、同字号**——颜色分离无效，探针也最容易把印刷体念成手写。而它恰恰是**最该擦干净**的东西：填空的手写内容就是原答，原答决定这次作答判对还是判错，印在重做纸上等于把上次的答案摆在你面前。

**决定 2 的第一版得到实测成绩。** 彩笔必擦这一半可靠（擦后残留彩笔 0）；模型框这一半**在"手写压进印刷体区域"的题上会伤印刷体**——两张真实照片里，手写只作为下划线落在题干下方的那张擦得干净（实擦 0.3%），而手写压在选项行上的那张啃掉了某一行 60% 的墨迹（实擦 12.1%，全图深色墨迹减少 19.3%）。这类题恰恰是错题本里最常见的情况。

**新的开放问题：擦除很可能只能是半自动的。** 机器给初值（颜色掩膜 + 模型框），你在预览里增删掩膜。理由是两侧失败都危险而机器两侧都不稳，而**审核本来就要看这道题的图**，顺势看一眼掩膜只多花几秒。若要走全自动，唯一的路是自己训一个分割模型（需要 GPU 与人工标注的掩膜）。

**已定：就走半自动。** 不做全自动，也不现在自训模型。于是"擦除"从一个自动流程降级为**审核动作的一部分**——这条反过来要求审核界面能把掩膜画出来并让人改，也就成了第一个必须做出来的界面。
