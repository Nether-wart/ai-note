# 模型端点由用户自决，不再限境内

## 背景

[ADR 0001](0001-file-backed-data-with-write-service.md) 与 [ADR 0008](0008-runtime-files-live-in-the-user-data-dir.md)
定了「数据只在本机」，[ADR 0003](0003-single-user-local-first.md) 在这之上又加了一条：
**模型调用限境内已核实的 endpoint（DashScope、DeepSeek），写成一份白名单常量**。
它的理由写在 0003 里，也很清楚：

> 它防的不是别人，是自己手滑：一张手写照片包含的信息一旦出境就收不回来。

问题在于**防的是谁**：这个项目是**单用户自用**，那个「手滑的人」与「读这段话的人」是同一个人。
把这条约束写死进代码，等于让代码替使用者做决定——而它挡住的恰恰是正当用法：把**识图**
（vision）与**解析／判定**（text）指向自己挑的模型（OpenAI 兼容端点、自建 vLLM、Ollama、
自架的转发……），以及本地那台不联网的推理机。

## 决定

1. `PROVIDERS` 从「白名单」**降为两家预设**（`dashscope` / `deepseek`）。任何 **OpenAI 兼容端点**
   都能由使用者在环境里定义：

   ```
   AI_NOTE_PROVIDER_OPENAI_BASE_URL=https://api.openai.com/v1
   AI_NOTE_PROVIDER_OPENAI_API_KEY=sk-...
   AI_NOTE_PROVIDER_OPENAI_MODEL=gpt-4o        # 可选
   ```

   角色再用 `<ROLE>_PROVIDER=openai` 指过去（角色表与逐角色模型选择都不变）。
   名字里的非字母数字统一换成下划线再大写（`my-proxy` → `AI_NOTE_PROVIDER_MY_PROXY_*`）。

2. **坏配置仍然起不来**：缺 `BASE_URL` 或 `API_KEY`、或该 provider 没有默认模型且角色也没给
   `<ROLE>_MODEL`，一律**装载时** `ValueError`。这条纪律不动——**不在第一次调用时才 401**。
   本机端点不需要密钥时，按惯例填一个占位值；**不留空**（留空与「忘了填」长得一样）。

3. `CONTEXT.md` 里那句「且限境内服务」随之删掉，改成「去哪一家由你自己配」。

## 后果

- **照片与答案可能离开本机、发到你自己选的那一家。** 出境从「被代码禁止」变成「由你决定」，
  这一句话必须写在 `.env.local.example` 与帮助页里——**选择权交出去的同时，代价也说清**。
- 模型质量、可用性、计费与合规不再由本仓库挑选与承担。
- 「换模型就要重跑验收，不过考不许上岗」这条纪律**不变**：端点自决只改"能用哪一家"，
  不改"换了一家要重新证明它够格"。

## 没有放开的部分（免得被读成"什么都放开了"）

- 数据仍然只在本机（ADR 0001 / 0008 不动）；离开本机的**只有模型调用**。
- 密钥仍然从环境／密钥文件读，**不进仓库、不进日志**。
- 真调网络仍然只发生在显式启用时（"不联网、不花钱"的验收口径与注入桩不变）。
- 服务只有绑定 `127.0.0.1` 这一种默认暴露面（绑 `0.0.0.0` 要显式给 `--public-base`）。
