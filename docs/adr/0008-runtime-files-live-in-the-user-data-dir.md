# 运行时的文件放用户数据目录，仓库里的 `data/` 只做测试语料

## 背景与决定

原先的默认值把两件事绑在项目目录上：数据目录是仓库根的 `data/`，模型调用留档是仓库根的 `runs/`。
两者都是**运行时产物**——它们是被用出来的，不是代码的一部分。绑在项目目录上有三个实际后果：

1. **代码与资料同生共死**：`git clean`、重新 clone、把分支切来切去，都可能碰掉资料；
2. **`git status` 要靠一串忽略规则兜底**：`.gitignore` 里六条专为「真数据别进仓库」而写——
   这些规则必须留着（防漏），但它们的存在本身说明位置不对；
3. **生产与测试抢同一个目录**：`data/` 既是你的真数据，又被当测试夹具用，于是
   「跑测试别写到真数据」变成一条要靠人记住的纪律，而不是结构上的保证。

决定：**运行时的文件放用户数据目录，项目目录只放代码与证据。**

1. **数据目录默认在用户数据区**：Windows `%APPDATA%\ai-note`（Roaming）、
   macOS `~/Library/Application Support/ai-note`、其它 `$XDG_DATA_HOME/ai-note`
   （没设就是 `~/.local/share/ai-note`）。`--data` / `AI_NOTE_DATA` 仍然优先。
2. **模型调用留档在同一目录下的 `runs/`**（`AI_NOTE_RUNS` 可单独覆盖）。留档是这份数据的档案，
   不是项目文件。
3. **仓库里的 `data/` 只做测试语料**：一份可以随时重造的夹具。本机测试可以读它、
   照它造夹具，但服务默认不再指向它。
4. **零第三方依赖**：不引 `platformdirs`，按平台环境变量自己推——`server/paths.py` 一个函数，
   一份表驱动的平台矩阵测试。
5. **默认值在用到它的那一刻算**（建 parser 时、构造 `Api` 时），不在 import 时算。
   `.env.local` 是在建 parser **之前**才灌进环境的，import 时算就等于让写在 `.env.local` 里的
   `AI_NOTE_*` 静默失效（[ADR 0007](0007-redesign-the-backend-contract-first.md) 第 6 条）——
   这个项目在 `.env.local` 上正好栽过一次同一类失败。

## 考虑过的替代方案

- **只把 `runs/` 挪走、数据目录留在仓库根**：第 3 条病因还在——生产数据与测试夹具仍是同一个目录。
- **引 `platformdirs`**：它正是干这个的，但会打破「`server/` 零第三方依赖」这条已经写进契约与
  `server/README.md` 的约束；为二十行代码换一个依赖不划算。
- **放 `~/.config/ai-note`**：配置放这里是惯例，但这里放的是**数据**（题卡、照片、留档），
  XDG 的 `data` 语义才对得上。
- **留档放 `$XDG_STATE_HOME`**：语义上也说得通（日志与状态），代价是「要备份什么」变成两个目录；
  这个应用只有一个用户、一份数据，不值得拆。

## 后果

- 直接 `python3 -m server.app` 就有对的默认值：数据在用户数据区，仓库里不会多出一个 `runs/`。
- `.gitignore` 里那几条**保留**：它们是安全网——你仍然可以显式 `--data data` 把服务指向仓库里的
  测试语料，那时也绝不许把私人数据写进仓库。
- 备份与迁移的对象从「这个仓库的 `data/`」变成「用户数据目录」；README 与 `data/README.md`
  写清了位置与那一条 `cp`。
- 已有数据的迁移是一次性动作，不是自动的：默认值变了以后，服务不会去翻仓库里的旧目录。
