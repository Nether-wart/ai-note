# 回到单用户：数据在本机，模型调用限境内

> **修订（2026-10）**：标题里「模型调用限境内」这一条**已被 [ADR 0010](0010-model-endpoints-are-the-users-choice.md) 取代**。
> 数据仍只在本机（本 ADR 与 ADR 0001／0008 的其余部分不动），但候选池不再是一条白名单常量：
> 任何 OpenAI 兼容端点都能由使用者自己定义——防手滑这件事改成由使用者自决，代价写在那条 ADR 的后果里。

## 背景与决定

第 1 轮复核推迟了多租户的运营能力，第 2 轮复核直接撤销整个多租户方向。

回看这条路的走向：最初的设计是**单用户**；被问到"写入服务与模型跑在哪里"时选了云 VPS；而"既然在云上、顺便让十几个人一起用"是**被部署方式顺带带出来的范围膨胀**。它引入的鉴权、隔离、配额分摊、备份策略与合规义务，没有一条服务于"帮我记住错题"这个目标。

因此决定：

- **单用户。** 没有账号、邀请、登录、数据隔离与配额分摊。写入服务跑在自己的机器上，手机经 Tailscale 或局域网访问；只有模型调用离开本机。
- **数据模型不带 owner。** 一题一文件，本地目录即数据库（见 ADR 0001）。
- **模型调用限境内已核实的 endpoint**（DashScope、DeepSeek），写成一份白名单常量。它防的不是别人，是自己手滑：一张手写照片包含的信息一旦出境就收不回来。
- **保留「按角色配模型 + 验收上岗」**（见 `CONTEXT.md` 的模型角色 / 验收 / 视觉探针）。这套机制与多租户无关，它防的是另一种静默失败：指向纯文本模型时，它不会报错，而是忽略图片、照提示词把题卡编出来。

## 考虑过的替代方案

- **维持轻量多租户**（ADR 0002）：功能上可行，但要在核心价值被验证之前先承担五件无关工作。
- **多租户数据模型 + 单用户部署**（第 1 轮的折中）：仍是过度设计——owner 字段永远不会被用到，却要在每一处读写里传下去。

## 后果

- ADR 0002 作废；为多租户准备的一切（owner、邀请、鉴权、隔离、配额分摊）都不做。
- "用户自带 provider 的出境边界"这个问题自动消失：只有一个用户，候选池由自己维护，边界收敛为一条白名单常量。
- 未成年人信息合规的面缩小为「自己的数据 + 境内模型服务」，不再承担替他人托管未成年数据的义务。
- **代价**：这东西只给你自己用。若哪天要给十几个人用，ADR 0002 里记的账要重新算一遍——这也是那篇不删除的原因。
