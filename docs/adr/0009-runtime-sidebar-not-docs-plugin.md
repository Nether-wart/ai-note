# 索引栏在运行时，不在构建期

## 背景

前端要一棵以**科目**为根的索引树：科目 →〔简报｜细则｜考点大纲｜今日重做〕，另有「未归类」兜底。这棵树里的三样东西都是**运行时数据**——科目、错题、简报——而 [ADR 0001](0001-file-backed-data-with-write-service.md) 与 [ADR 0006](0006-docusaurus-base-with-tauri-compatibility.md) 已经定了「数据变更永不触发 Docusaurus 重建」「**录入一道题绝不触发重建**」。

矛盾出在 [ADR 0006](0006-docusaurus-base-with-tauri-compatibility.md) 的决定第 1 条后半句：它把「**考点大纲**这种层级知识树」指派给 Docusaurus 的**原生文档能力**（docs 插件）。docs 插件的侧栏是**构建期**从文件系统扫出来的，而这棵树里混着运行时数据，两者不能共存于同一份侧栏。

两条路的代价都很清楚：

- 交给 docs 插件 = 「录入一道题」必须写入内容文件并重建站点。这正是 ADR 0001 已经否掉的那个方案，它当时的理由值得原样重读：把写入放在构建管线里，会让「录入一道题」变成「等一次完整构建」，**这在手机上录题时是不可接受的摩擦**。
- 运行时自绘 = 放弃 docs 插件的 MDX 与文档主题生态，侧栏（高亮、展开折叠、长列表）要自己实现。

## 决定

**索引树由前端自己在运行时绘制；不启用 docs 插件。**

1. 侧栏是一个运行时 React 组件，取 `GET /api/index`（以及简报端点），自己渲染科目树。数据一个字节都不进构建产物。
2. 视觉与交互向 Docusaurus 的文档侧栏看齐（套用它的主题 CSS 变量与类名），但**不共用它的实现**。
3. **考点大纲成为运行时数据**：它挂在该科目下，取自受控词表，与错题走同一条读取路径。
4. ADR 0006 决定第 1 条后半句不再执行；那一半以「修订」小节的形式记在 ADR 0006 里，**不静默删改**（见 `docs/agents/domain.md`：与既有 ADR 冲突要显式说出来）。

规格正文在 issue [#17](https://github.com/Nether-wart/ai-note/issues/17)。

## 考虑过的替代方案

- **启用 docs 插件，录入时写 MDX 并重建**：能白拿导航与文档生态，但把「录入」变成「等构建」，与 ADR 0001 的结论正面冲突，且那正是 ADR 0001 明确否掉的方案。
- **混合：docs 插件只放不常变的说明页，数据走自绘栏**：两套导航并存，人会分不清哪一层是数据、哪一层是文档；而说明页本身没有非它不可的内容（真正需要读的东西是简报与阅读页）。

## 后果

- 侧栏的高亮、展开折叠、长列表性能（细则里可能有上千道题）都是**我们自己**的责任，不再是主题给的能力。
- 「索引树长什么样」从此只有一份实现，而且它在运行时：改它不需要重建，也不需要重启服务。
- 站点仍是纯静态 bundle，ADR 0006 的 Tauri 兼容那条约束不受影响。
- **一条必须守住的兜底**：侧栏要有「未归类」一栏兜住没有科目的错题，数量写在栏上。任何「某道题不在树上」的情形都是缺陷——这个项目最怕的失败是**静默少一道题**。
