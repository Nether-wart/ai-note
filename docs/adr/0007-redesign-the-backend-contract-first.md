# 重新设计后端：契约优先，`proto/server.py` 只是原型的证据

## 背景与决定

`proto/server.py` 是原型的证据，不是生产服务的草稿。它把三件事混在一个文件里：数据读写（一题一文件 + 派生索引）、模型与图像处理（抽取、手写定位、擦除、像素统计）、以及**页面渲染**（清单页、活页纸、标记页三个手写 HTML 视图）。十轮实测证明了它承载的那些**决定**是对的，但代码是按「最快验证」写的。

决定：**后端从零设计，不演化它。起点是契约，不是实现。**

1. **契约优先。** 先把接口定下来（一份人类可读的契约文档，加前端要用的类型），再写实现。契约是唯一必须跨得过去的东西：将来用 Rust 重写实现、或把服务塞进 Tauri 的进程生命周期，都只是换实现、不换契约。
2. **职责边界。** 后端负责：数据读写（一题一文件、一页一文件）、派生索引、模型调用（抽取／判定／定位／擦除探针）、图像处理（裁剪、擦除、墨迹与像素统计）、状态机（掌握与冷却）、批次与页锚点、审计与修复。后端**不负责渲染页面**——不做模板、不管界面状态。但它**托管静态资源**（手机上传页、图片、前端产物）：托管文件不是渲染。
3. **实现语言暂时仍是 Python。** 十轮实测的资产（擦除、闸门统计、裁剪体检、逐字打磨过的提示词与阈值）都在 Python 里，重写它们等于把验过的证据重赌一次。契约先行让「换 Rust」成为一个可变现的、局部的决定，而不是一次赌博。
4. **录入入口：多路进同一个管道。** 录入的定义收敛成一句话——**往收件目录放一个文件**：
   - **电脑上**：拖拽或放进收件目录；一个文件夹 = 多页（批量）。
   - **手机上**：浏览器打开一个极简上传页——拍照／选图 → 上传 → 立刻看到切分结果 → 确认入库。**不装应用**：把一个本地数据应用装到手机上、再让它把数据传回电脑，比「打开一个网址拍张照」重得多，而录入摩擦是这个项目的生命线。
   - **同步盘（若你在用）**：照片落进收件目录，后端监视它。
   - 三条路之后走同一条管道：页 → 切分 → 审核队列。
5. **对外可达地址必须显式可配。** 页锚点、以及手机上要打开的上传页链接，都必须用**手机真能访问到的地址**。原型的 `ANCHOR_BASE = f"http://{args.host}:{args.port}"` 在为了手机访问而绑 `0.0.0.0` 时会生成一个手机访问不到的地址——这是一处已查到的债务。新后端有一个显式的「对外地址」配置，默认值可以推导，但必须能覆盖。
6. **一条贯穿契约的约束（项目宪法）：不许静默。** 每个响应都带「我做了什么、我没做什么」的显式字段（警告、被跳过的原因、降级说明）；**每个由人填写的字段都要有一个会喊的检查**。这不是文风偏好，是十轮实测里唯一反复出现的失败模式。

## 考虑过的替代方案

- **演化 `proto/server.py`**：省一次重写，但会把它的混合职责（渲染 + 数据 + 图像）带进生产，而 ADR 0006 要求界面能整体换掉。
- **现在就换 Rust**：终态最干净，但要把十轮实测的图像处理重赌一次。
- **给手机做一个 Tauri 应用**：Tauri 有移动端，但要处理安装、更新、权限，以及「数据怎么回到电脑」；与「打开一个网址」相比是纯粹的摩擦。
- **只做目录监视、不做上传页**：最省事，但只用手机的场景下无法录入（整册相册同步会把无关照片一起吸进来）。

## 后果

- `proto/` 冻结为只读参考：提示词、阈值、统计口径与实测结论被继承，代码不被继承。
- 后端与界面之间只剩 JSON 契约，于是「界面是 Docusaurus 站点 / Tauri 窗口 / 手机浏览器」成为同一件事的三种外壳。
- 手机上传页是后端托管的一个独立单文件页面（无构建步骤），不依赖 Docusaurus 产物——手机上不该为了拍一张照片下载整个前端。
- 目录布局（本 ADR 一并定下）：`server/` 新后端 · `site/` Docusaurus 站点 · `data/` 数据（私人，不入库）· `proto/` 冻结的原型 · `docs/` 设计记录。
- **待验证**：目录监视在多平台上依赖轮询（`inotify` 在某些挂载与同步盘上不可靠），所以「监视」必须有一个可手动触发的等价入口（一个按钮或一条命令），不能只有自动这一条路。
