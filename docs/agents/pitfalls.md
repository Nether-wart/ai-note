# 已经咬过人的坑

这份不是风格指南，是**清单**：每一条都真的在这个仓库里发生过，坑的形状与当时的症状都写下来，
免得下一个人（或下一个我）换个地方再踩一次。

写法：一条 ＝ 「症状 → 为什么会有这个坑 → 规矩」。**只收真的发生过的**——
没发生过的不写，否则清单会长成一份没人读的清单。

---

## 1. 在指令行里塞中文解释 → 指令本身被当成非法

**症状**：`ruff check server/` 报

```
warning: Invalid `# noqa` directive on server/config.py:140:
expected code to consist of uppercase letters followed by digits only (e.g. `F401`)
```

**为什么**：`# noqa: E501（这一句就是要长到能点名两个可改的地方）`——指令的语法只认
「大写字母＋数字」，后面那串中文把它变成了**非法指令**。同一个会话里咬了两次
（前一次是 `# noqa: N802（http.server 的命名约定）`），所以它不是手滑，是习惯。
更气人的是：那一行本来也不超长，**这条 `# noqa` 根本不需要**。

**规矩**：说明写在**上一行的独立注释**里，指令行只留指令（`# noqa: E501`）。
写 `noqa` 之前先看 `ruff check` 到底报不报——不报就别加。

**同族的还有一条，同一个会话里撞了 5 次**：把中文散文写进**只接受标识符**的地方——
测试函数名里的空格、名字里带的引号、以及最阴的**全角括号**（`def test_…（最坏的一种）():` →
`SyntaxError: invalid character '（' (U+FF08)`）。它偶尔能跑，所以看起来像手滑；**它其实是习惯**：
先在脑子里写好句子，再往里塞代码。**写标识符时只想标识符**——中文名一律用下划线连，
标点/引号/括号一个都不许有。

## 2. 解释某条禁用写法的注释，把这条检查自己判红了

**症状**：`site/tests/bundle-safe.test.mjs` 报 `src/lib/time.js: [...byMonth.values()]`——
可那一行明明已经改成 `Array.from(...)` 了。

**为什么**：检查扫的是文件原文，而**解释这条规矩的注释里必然出现那个坏写法**
（「不许写成 `[...byMonth.values()]`」）。这与第 1 条是同一个家族的坑：
**自指**——纪律的说明文档反过来触发纪律。

**规矩**：任何"扫源码"的检查先 `stripComments()` 再扫。同时给检查配一条
**"对坏写法会响"的自证用例**，否则它可能是一条永远绿的判据。

## 3. `pkill -f "<模式>"` 的模式匹配到了自己的命令行

**症状**：一条命令跑到一半整个 shell 被杀（`exit code 143`），后半截什么都没执行。

**为什么**：`pkill -f "remote-debugging-port=9222"` 的命令行**自己也包含这个字符串**，
于是它把自己那条 `bash -c` 杀了。

**规矩**：别用 `pkill -f` 清理自己刚起的进程；用受管后台任务的句柄（`job_kill`），
或者换一个只描述目标的模式。**清理动作要确认目标，不要用会匹配到自己的模式。**

## 4. `[...map.values()]` 在浏览器里崩、在 node 里全绿

**症状**：`node --test` 140 passed，浏览器里细则页**整页崩**：
`Cannot read properties of undefined (reading 'slice')`，堆栈指向
`Array.map(...).slice`。

**为什么**：打包器在 loose 模式下把 `[...iterable]` 编译成 `[].concat(iterable)`，
而 `concat` **不展开迭代器**——它把 MapIterator 本身当成一个元素装进数组。
源码语义是对的，坏在**变换**那一步。node 不做那个变换，所以一路全绿。

**规矩**：迭代器／集合展开一律写 `Array.from(...)`（普通调用，任何模式语义一致）。
`site/tests/bundle-safe.test.mjs` 在源码层拦这一条。

## 5. 背景进程用 `(cmd &)` 起，随那次调用一起死

**症状**：上一步起的服务，下一步 `curl` 就是 `000`；或者浏览器/静态服务"明明起过"却连不上。

**为什么**：每个 bash 调用跑在自己的沙箱里（`bwrap --unshare-pid --tmpfs /tmp`），
`(cmd &)` 起的进程随那次调用结束而消失；`/tmp` 也是每次调用独立的。

**规矩**：跨调用要活着的东西用**受管后台任务**（`run_in_background`），
并把产物写到工作区内（`.verify/`），不要指望下一次调用还能看到 `/tmp` 里的东西。

## 6. 长跑的服务接进 `| head` → 被 SIGPIPE 带走

**症状**：服务起了一次就再也没响应；重起时报「端口已被占用」，而 `curl` 又是 `000`。

**为什么**：`python3 -m server.app … | head -8`——`head` 读满 8 行就退出，管道断开，
服务写日志时吃到 SIGPIPE，并且是在**第一次请求**时死掉，于是端口像是"被占着但没人应答"。

**规矩**：长跑进程不接 `head`／`grep` 这类会提前退出的下游；输出交给后台任务的捕获。

## 7. 只在一种环境下成立的"证据"

**症状**：说"量过了，几何是对的"，其实那次测量根本没带 `--window-size`，
量到的是 800px 宽下的堆叠布局；三遍返工都建立在这份错证据上。

**为什么**：工具本身的参数没进证据，而**读数是"像真的"的**——它们确实是一组自洽的几何数字。

**规矩**：把量尺的**关键参数**写进结论（视口宽度、URL、选择器）。
读数与自己预期不符时，先怀疑量尺，不要先怀疑被量的东西。
