规则（见 `CONTEXT.md` 的「验收」）：每个模型在每个角色上岗前必须过两道——**视觉探针** + **该角色的通过标准**。换模型就要重跑，不过考不许上岗。

### judge 角色的考卷

三份自出题（根式有理化、区间开闭、多解）+ 两份人写固定考卷（`proto/fixtures/cases-radical.json`、`cases-interval.json`）。全部判对，置信度 ≥ 0.95。

挑几个值得记住的用例：

| 标准答案 | 待判答案 | 期望 | 实际 |
|---|---|---|---|
| `x=2√3/3` | `x=√12/3` | 等价 | ✓ |
| `x=2√3/3` | `x=√3/3` | 不等价 | ✓ |
| `x=2√3/3` | `x=-2√3/3` | 不等价（符号） | ✓ |
| `(1,2)` | `(1,2]` | 不等价（端点开闭） | ✓ |
| `(1,2)` | `(0,2)` | 不等价（左端点） | ✓ |
| `x=±2` | `x=±√2` | 不等价（似而不同） | ✓ |
| `x=±2` | `x=±√4` | 等价（√4=2） | ✓ |

### 方法论备注

模型自出的用例有"自出自考"的偏向（它会往自己擅长的方向出题），所以另配了人手写的固定考卷。

**以后每换一次模型，两份考卷都要重跑**：自出题看广度，人写题看准度。

### extract 角色的考卷：两张真实照片 × 两个模型

照片：`samples/1-0000.png`（解答题，印刷题干＋整页黑笔手写错解）、`samples/2.png`（选择题，印刷题干＋红黑两色笔手写）。

**一个方法上的限制**：我（本会话的模型）看不了图，所以"直接可用率"不能由我目测。改成两条不依赖眼睛的考法：

1. **两模型交叉互校**——同一张图跑两个模型，分歧处就是风险处；
2. **纯文本可验的部分我自己验算**——正解与标准答案的正确性不需要看图。

| 字段 | 1-0000.png（解答题） | 2.png（选择题） |
|---|---|---|
| 题面图裁剪 | ✓ **客观验证正确** | ✓ 两模型都框全了内容；B 的右边距只有 2px，偏紧 |
| 题型 | ✓ `solution` | ✓ `choice` |
| 题面转录 | ✓ 完整，连题末提示 `√42 ≈ 6.48` 都在 | ✓ 完整，四个选项都在 |
| 原解转录 | ✓ 忠实记下学生的错（`k=1200`、`(0,80]`、第 (2) 问停笔） | ⚠ **两模型不一致**：A 说圈选选项"形似 C"，B 说题号旁红笔标注 A |
| 正解 | ✓ **独立验算通过** | ✓ **独立验算通过** |
| 标准答案 | `null`（解答题按设计不机判） | `'A'` ✓ 正确 |
| 考点 | 极值与最值（勉强） | B 提案了两个缺失标签，A 硬套现有标签 |

**正解的独立验算**（这两道题的答案我自己算过，不依赖模型）：

- 隧道题：堵塞条件 `x=110, v=0` ⟹ `60−k/30=0` ⟹ `k=1800`（学生算成 1200）。(1) `60−1800/(140−x) ≥ 40` ⟹ `140−x ≥ 90` ⟹ `x ≤ 50`，即 `(0,50]`。(2) 令 `t=140−x`，`y = 60[170−(t+4200/t)] ≤ 60(170−20√42) = 10200−1200√42 ≈ 2423.1`，取等 `t=10√42`，即 `x=140−10√42 ≈ 75.2`。**模型给的全对**，且 `deepseek-flash` 明确点出了学生的算术错误。
- 充分不必要条件题：`∃x∈[1,4]: x²+ax+4≤0 ⟺ a ≤ max(−x−4/x) = −4`，故原命题 ⟺ `a ≤ −4`，充分不必要 = `a ≤ −5` = **A**。**两模型都答对**。

**裁剪的客观验证**（不靠眼睛）：把页面按墨迹分离（深色＝印刷体候选，高饱和＝彩笔手写），再逐行统计墨迹列数与最右位置，就能反推出文本行的实际范围：

- `2.png`：题干在 y24–40（右端 x348），选项行在 y64–72（右端 x525）→ 两个框都框住了内容。
- `1-0000.png`：框右边界外 **0** 像素墨迹，框下方 6158 像素墨迹（全是手写解答）→ 框恰好只含印刷题干，正是重做纸要的。
- 这个检查的弱点：**黑笔手写和印刷体在灰度上同色**，颜色分离在整页黑笔的 `1-0000.png` 上失效，只能退化为"墨迹分布"证据。

**两模型的差别**（同样输入，同一份提示词）：

| | `deepseek-v4-flash-vision-exp` | `deepseek-flash`（V4.1） |
|---|---|---|
| 隧道题 token | 7,793 | 21,414 |
| 是否点出学生的算术错误 | 未点出，只标注"形似 1200，与题设不符" | **点出** `60×30` 误算为 1200，并用题末 `√42≈6.48` 提示反证 `k=1800` |
| 缺失标签 | 硬套现有考点 | **提出标签草案**（`集合与逻辑/充分条件与必要条件`），不硬套 |
| 载体差异 | 输出 LaTeX（`$x^2$`） | 输出纯文本（`x²`） |

LaTeX 那一条对打印有影响：Docusaurus 带 KaTeX，LaTeX 能直接渲染；纯文本的上标符号也能读，但排出来不如 LaTeX 齐整。**这可能是判定"哪个更适合当抽取模型"的一条独立理由。**

### 考核暴露的原型缺陷（已修）

同一张照片重跑 `extract` 会**静默覆盖**上一次的题卡（题卡按照片哈希命名）。这次两个模型各跑一遍，第一个模型的题卡就被第二个覆盖了，只好从 `runs/` 日志里捞证据。已改为覆盖前打印警告，并带上"上次是谁抽的、什么时候"。

### 第二轮：人工定案推翻了机器读数

对上表中的分歧，人工给出的真相是：**学生原答是 C（错），红笔的 A 是订正后的答案**。也就是说：

- `deepseek-v4-flash-vision-exp` 读到了 C 的圈选痕迹，但因为不确定而没写进转录（保守但丢了信息）；
- `deepseek-flash` 读到了红笔 A，**把它当成了学生的所选答案**（若不自查，这张卡会看起来"学生答对了"，一道真错题就溜出了错题本）。

**根因不在模型，在题卡 schema**：当时的 `EXTRACT_SYSTEM` 里根本没有"订正"这个概念，也没有任何字段问"学生原本答的是哪个"。两个模型只能即兴发挥，于是各自猜错一半。

修法（两步，都已完成）：

1. `CONTEXT.md` 新增两个领域术语：**原答**（学生原本给出的最终答案，决定判对判错）与**订正**（后来补上的正答/批注，常是红笔，不是原答、也不等于 AI 的正解）。
2. `EXTRACT_SYSTEM` 增加第 4 条铁律：原答与订正必须分开记；**看到订正里的正答不等于学生答对了**；分不清就 `original_answer` 填 null、压低置信度并在 notes 里说明。校验器再加一条：有订正却没有原答 → 记警告、要求人工确认。

重考同一张 `2.png`（换成补了字段的新提示词）：

| | `deepseek-flash` | `deepseek-v4-flash-vision-exp` |
|---|---|---|
| 订正识别 | ✓ 红笔 A 归入 `correction_transcript` | ✓ 红笔 A 归入 `correction_transcript` |
| `original_answer` | **null** + 触发"有订正无原答"警告 | **`'B'`**（置信度 0.35） |
| 与真相（C）比 | 保守正确地落到「看不清」 | **猜错了**，还是个具体断言 |
| token | 5,835 | 20,228 |

结论：**抽取角色维持 `deepseek-flash`**。在补上规则之后，它是两个模型里唯一严格遵守"看不清就留空"的那个。

### 关于成本对比的一处更正

上一节写了"`deepseek-flash` 的 token 约 2 倍"，那是单题观测。两题合起来：隧道题 flash 2.7 倍，选择题 exp 3.5 倍——**互有高低，不是稳定的成本差异**。选型不该拿 token 当主要依据。

### `cropcheck`：裁剪框体检（常驻命令）

不用眼睛也能查出两类错误：**框小了**（框外相邻条带里还有成片墨迹）与**框里混进了彩笔手写**。它对现有两张卡的体检结果：

| 题卡 | 框内深色墨迹 | 框内彩笔 | 判定 |
|---|---|---|---|
| `1-0000.png`（解答题） | 5811px（3.9%） | **0px** | ✓ 干净；框下 6152px 是手写解答，本就该排除 |
| `2.png`（选择题） | 926px（1.9%） | **453px** | ⚠ **框内有红笔订正**——重做纸会把答案一起印出来 |

**已知弱点**：黑笔手写与印刷体在灰度上同色，机器分不开。所以它报不出"框里混进了黑笔手写"，也判不了"框是否恰好等于题干"。它能说的只有"框小了"和"框里混进彩笔"这两件——而这两件恰好是最有害的。

### 由此暴露的一个真问题：重做纸会泄露答案

矩形裁剪**无法排除压在题干区域上的手写**。`2.png` 就是实例：订正的红笔 A 就写在选项上方，任何包含选项的矩形框都会把它带进来。而重做纸一旦印出订正过的正答，重做的意义就没了。

这不是排版细节，是"题面用什么载体"的分叉：

- **照片裁剪**：绝不改变题意，但会带上手写与订正（泄露答案）、费墨、版面不齐；
- **转录文字重排**：干净、不泄露、省墨、可缩放，但**转录错一个符号就改变了题目**，而你没做错这道题、往往看不出来。

**已定**：重做纸印转录文字、复习纸印照片（[ADR 0004](adr/0004-redo-sheet-prints-transcript.md)）。这个决定反向要求转录必须是**可渲染的 LaTeX**，并直接引出下面第三轮。

### 第三轮：载体变了，于是转录格式成了验收项；而原答字段跑间不稳定

按 ADR 0004，重做纸印转录文字，所以提示词新增两条要求（数学一律 LaTeX、选择题的选项拆进 `options` 数组）。重抽结果：

| | 结果 |
|---|---|
| `2.png` 题面 | `$6.$ “$\exists x\in[1,4]$，$x^{2}+ax+4\le 0$”的一个充分不必要条件是（ ）` ✓ |
| `2.png` 选项 | 4 个，结构化，各自是 LaTeX ✓ |
| `1-0000.png` 题面 | 含 `$$v=\begin{cases}50, & 0<x\le 20\\ 60-\dfrac{k}{140-x}, & 20<x\le 110\end{cases}$$` ✓ 分段函数排得出来 |

但同一个模型、同一张图、同一份提示词，连跑三次，最危险的那个字段是这样的：

| 第几次 | `original_answer` | 置信度 |
|---|---|---|
| 1（旧提示词，还没有这个字段） | 字段不存在；红笔 A 被写进原解转录，note 里称它"疑为所选答案" ✗ | — |
| 2（补了原答/订正规则） | `None` ✓ | 0.2 |
| 3（补了 LaTeX 要求后） | **`'A'`** ✗——正是订正里那个 A | 0.4 |
| 4（加了兜底规则后） | `None` ✓ | — |

**结论：这个字段跑间不稳定，不能靠模型自觉。** 于是在校验器里加了三条机械兜底（不依赖模型是否听话）：

1. **原答与订正转录撞车**（原答是单个字母、且该字母出现在订正转录里）→ 警告"很可能把订正误当成了原答"；
2. **原答与标准答案相同** → 警告"这是错题本，请确认这道题确实做错过"；
3. **原答置信度 < 0.6** → **强制置为 null** 并警告。低置信度下猜一个答案，比留空有害得多；而"看不清"是设计里明确允许的落点。

第 3 条是关键：它把"低置信度下猜一个"这一整类失败从代码层抹掉了，而不是指望提示词约束住模型。代价是原答会经常留空、需要人在审核时补——这恰好是「先入库后审核」本来就要人干的事。

另外两条新增的粗检：选择题没有可用的 `options` 结构 → 警告（重做纸排不出选项）；题面转录里 `$` 数量为奇数 → 警告（LaTeX 没闭合，印出来会毁掉整张纸）。

顺带记一处观察：`deepseek-flash` 在 notes 里两次提出"学生最常见的错选是 B"，而真相是 C。它对"学生会怎么错"的先验是错的——这类先验**不能**用来兜底，这也是必须留 null 交人工的原因。

### 第四轮：重做纸改成「原题照片 + 擦除手写」，第一版只做到了一半

人工把决定改了（[ADR 0005](adr/0005-redo-sheet-prints-cleaned-photo.md)）：重做纸仍印**原题照片**（题意绝不改变），但必须擦掉手写字迹，而不是印转录文字。于是新增 `clean` 子命令，第一版只擦**彩笔**（订正含答案，是必须擦净的那一类；彩笔有颜色可分，用颜色掩膜 + 邻域背景填补即可，不需要模型——本机没有 cv2、没有 GPU，实现只用 numpy + PIL）。

实测（`clean --verify`）：

| 页面 | 彩笔像素 | 擦除后残留 | 彩笔压在印刷体上 | 泄漏探针 |
|---|---|---|---|---|
| `2.png` | 211（0.7%） | **0** | 13px（印刷体可能有缺口） | **✗ 没通过** |
| `1-0000.png` | **0**（整页黑笔） | — | — | 第一版对它完全无能为力 |

探针的判词是：`这张图上有手写字迹，手写内容为：∀x∈[1,4], x²+ax+4>0 以及选项旁的 C.`

三条结论：

1. **机制有效**：彩笔擦除后残留为 0，颜色分离这一半是可靠的。
2. **标准比第一版高**：擦掉彩笔之后，黑笔手写完整地留在图上，而探针立刻读出了它——连学生圈选的 **C** 都读出来了。要满足"重做纸上没有任何手写"，必须有能区分**同色黑笔手写与印刷体**的方法，颜色分离做不到。
3. **仪表先于方案到位了**：现在有了三件可量化、可复用的东西——`cropcheck`（框对不对）、`clean` 的残留统计（擦干净了吗）、泄漏探针（擦完还读得出来吗）。所以接下来试任何擦除方案，都能当场量出它值不值得用，而不必先相信论文或宣传。

另外那个 `C` 值得单独记一句：它是学生的**错答**（正解是 A），所以它泄露的不是答案而是你自己的错误思路。这仍然是泄露，但危害等级低于泄露订正——这也是 ADR 0005 里把"订正"列为必须擦净、"原解"列为尽力擦净的依据。

### 第五轮：让模型标手写框来擦黑笔——一半可靠，一半伤印刷体

按"先试视觉模型给手写框"这条路做了 `clean --boxes`：模型标出手写位置的归一化框，把它们并进掩膜一起擦。

**新抓到一个真 bug**：第一版擦完反而**多出 3015 个深色像素**、平均亮度下降。查下去是 `np.pad(mode="edge")` 把**已置零的边缘像素**复制出去，让贴着图像右边缘的手写框在邻域里找不到纸色，邻域最大值退化成 0，于是填出了一道黑边。改成补零 + 全局纸色兜底后，两张图"新出现的深色像素"都回到 **0**。这个 bug 两个探针都没发现（它们当时回的是"没有手写""印刷体完整"）——所以客观统计不能省。

**框路线的成绩**：

| 页面 | 手写位置 | 模型框 | 实擦占比 | 逐行墨迹损失 | 判定 |
|---|---|---|---|---|---|
| `1-0000.png` | 只在题干下方（下划线） | 3 个 | 0.3% | 无一行 >30% | **可用** |
| `2.png` | **压在选项行上** | 3 个 | 12.1%（全图深色墨迹 −19.3%） | y=18 行 20→8px，**损失 60%** | **伤了印刷体** |

也就是说：手写没有侵入印刷区时这条路干净可用；一旦手写压在题干/选项上（错题本里最常见的情况），大框会连印刷体一起擦掉。模型给的框长度是墨迹面积的十倍量级，精度不够。

**探针被证明不能当闸门**（同一张图连问三次的对照实验）：

| | 泄漏探针 | 损伤探针 |
|---|---|---|
| 擦除客观良性的那张 | `有手写：60` / `没有` / `没有` → 1/3 误报 | `完整` / `有白线涂抹` / `完整` → 1/3 误报 |
| 擦除客观有伤的那张 | 三次都指到受损处 | `完整` ×3 → **3/3 漏报** |

闸门因此改为确定性统计 + 人眼：残留彩笔像素、新出现的深色像素、逐行墨迹损失、实擦面积占比。模型判词只当线索。详见 [ADR 0005](adr/0005-redo-sheet-prints-cleaned-photo.md) 的"实测后的修订"。

**误报已由人手确证**：探针在擦除良性的 `1-0000.png` 上坚称"手写填写了数字 50 / 该数字被白线涂抹无法辨认"，而原卷上那个 `50` **是印刷体**（用户确认）。定位那一步没有漏标——漏的是探针的可靠性。它盯着的正是"印刷体数字坐在填空式位置上"的地方，而这恰好指向本任务最难的一类题：**填空题里学生的作答与印刷体同色、同行、同字号**，颜色分离无效、探针也最容易把印刷体念成手写，而它偏偏是**最该擦净**的东西（填空的手写内容就是原答）。

**开源权重核实结果**：[DocUnfold](https://github.com/CXH-Research/DocUnfold) 仓库里只有 `models/DocUnfold.py`（网络定义）、`train.py`、`infer.py`、`config.yml` 与数据集链接，**没有预训练权重**。要用它就得自己训，而本机没有 GPU 驱动。所以"现成的轮子"目前并不存在可用形态。

### 第六轮：第一个界面（打印清单页）+ 写入服务的第一个端点

按"擦除定为半自动"的决定，做了 `proto/server.py`：一个本地写入服务，一个页面同时承载**审核**（擦除结果、原答与订正、标准答案与正解、考点错因、标签提案）与**打印**（版面格、页锚点、可打印的 A4 活页纸）。它同时也把 ADR 0001 的派生索引落了地（每次写入后重建 `data/index.json`）。

**做出来之后，用它本身又抓到两个 bug：**

1. **闸门语义错了。** 原来那条"受损行"统计的是"墨迹减少超过 30% 的行"，而**擦掉一行手写本来就会让那一行的墨迹减少**——那是预期结果，不是损伤。它把"擦对了"报成"擦坏了"（`2.png` 上报 5 行、最差一行只剩 27%，看起来很吓人）。改成**疑咬印刷体**：被擦掉的墨迹若**左右两侧都还有墨迹**（窗口 ±2~12px），它像是落在印刷笔画中间——那才是在印刷体上啃了个洞。改后读数：`2.png` 6px、`1-0000.png` 2px，从"看似重伤"变成"两个小可疑点，人看一眼"。
2. **题型枚举没对上。** 题卡里存的是 `choice|fillin|solution`（英文枚举），而版面格的初值表我写成了中文键（`选择`/`填空`/`解答`），于是**每一道题都静默退回默认值 2 格**。又是静默失败，又一次说明"没有报错"不等于"做对了"。修法是键改成真实枚举，并加 `TYPE_CN` 只用于显示。

**顺带确认了一条规则是对的**：新录入的两道题都在冷却期内（`created_at` 就是当天），所以**默认打印清单为空**——这正是 `CONTEXT.md` 里"未毕业且已脱离冷却的题才默认印"的定义。缺的只是界面上那个"显示冷却中的题"开关，现已补上。

**当前状态**：活页纸能出了（2 题排成 2 页：解答题占满 4 格一页，选择题 1 格；页锚点 `P1-9D49` / `P2-62F9`，页脚含本页题目名单）。两张题卡的闸门都亮着 ⚠（疑咬印刷体 6px / 2px）——**下一步就是把掩膜在界面上过一遍**：这正是半自动设计要做的事，也是第一次由人而不是由探针来当裁判。

### 第七轮：界面"拖完框不更新"——又是静默失败，这次在我自己写的界面上

第一个用户反馈的 bug：**拖完框，结果不更新**。根因：渲染 `<details>` 时我只写了 `data-pid`、**没写 `id`**，而 JS 用 `document.getElementById('p-' + pid)` 取题目块 → 返回 `null` → `querySelector(sel, null)` 退化成"在整个文档里找第一个匹配项"：读数写进了第一题的位置，第二题的按钮被绑成了第一题按钮的处理器。**页面上没有任何报错，只是不再更新**——和题型枚举退回默认值、和探针不报错地编造，是同一种病。

写入本身是好的：事后查题卡，用户拖的那些框**全都存下来了**（2 张卡分别是 2 加 2 减、1 加 6 减），而且闸门读数从"疑咬印刷体 6px / 2px"变成了 **0px / 1px**——在看不见结果的情况下盲拖，居然把印刷体损伤抹平了。

改法（四件事，都是把"静默"换成"响声"）：

1. 给题目块补上真 `id`，并把 JS 的取值助手 `q()` 改成**找不到就抛错**，不许退让。
2. 顶部加一条**反馈条**：每次编辑后显示"✓ <题号> 减了一笔 · 已重算"，失败则红条显示原因。
3. 拖拽状态改成全局：**松开鼠标时哪怕指针已经离开图片也照样落笔**；读数里加上"深色墨迹 887→836"这种必然随掩膜变化的数字（同一张图、同一处，改没改一眼可辨）。
4. 加 `python3 proto/server.py --selftest`：**不靠浏览器**检查界面不变量（每个题目块有 id、块内该有的元素都在、页头控件齐全）。并且我故意把 id 抹掉复验了一次——自检确实会响。

第 4 条自己也有个插曲值得记：自检的第一版报了 20 条"块内缺少"，**全是误报**——我在 HTML 里查的是 CSS 选择器写法（`.gates`），而页面里写的是 `class="gates"`。判据写错时它响亮地报了（好方向），但错的就是错的。改对之后复验才算数：一个从没失败过的检查，和一个从没通过过的检查，同样不可信。

### 第八轮：半自动走通全绿 —— 以及它顺带暴露的一次答案污染

**结果**：两张题卡的闸门都到了「新出现深色 0 · 残留彩笔 0 · 疑咬印刷体 0px」。这是这套设计里第一次由人（而不是探针）把擦除判到合格，也第一次验证了 ADR 0005 押的那个注：**机器给初值、人修，是能做到的**。

**代价（这是第一次量到，不是估的）**：两题一共 12 笔人工修正——`41c86b` 加 2 减 2，`ef7c47` 加 1 减 7。方向很清楚：**12 笔里 9 笔是"减"**，即删掉模型多给的框。机器在"标出所有手写"这件事上系统性过度：`ef7c47` 模型给 4 个框，人砍到只剩 1 笔加；那些被减掉的框是学生划变量名的下划线，留着既不泄漏答案也不碍事。这印证了 ADR 0005 的分级判断（不是所有手写都必须擦，只有订正与作答危险），也给出下一步的量化理由：**定位应该问窄——只找"原答与订正写在哪"，而不是"所有手写"**。

另一个值得记的对照：`41c86b` 的人工修正让**实擦面积从 2673px 涨到 3442px**（8.4%→10.8%），同时**印刷体损伤从 6px 降到 0**。面积更大、损伤更小——说明"擦干净"与"别擦坏"这两个方向确实在互相拉扯，而人能同时满足，机器单独做不到。

**顺带抓到的一次真事故（脏数据比没数据更危险）**：界面那个"不回显"的 bug 不只是不回显——旧代码里第二题的按钮被绑到了第一题的处理器上，于是**第一题的 原答 `C` / 标准答案 `A` 被写进了第二题**，而第二题是解答题（隧道车流量），它现在带着标准答案 `A` 被标成"已审核"。这类数据会让自动判定拿 `A` 去判一道解答题。

改法是给审核字段加一层自检 `card_warnings()`：题型与答案形式不匹配（解答题的标准答案只有单个字母／选择题的标准答案不是字母）、原答与标准答案相同、考点为空、标为已审核却缺标准答案。它**既拦保存、也在列表页暴露存量脏数据**——所以是它先把上面那次污染查出来的（对 `ef7c47` 报 4 处、对 `41c86b` 报 0 处，正中靶心）。教训和前几轮一致：**每一处由人填写的字段，都得有一个会喊的检查**，否则错误只会安静地留在库里。

### 第九轮：闭环的最后一截（打印批次 + 页锚点 + 判定回写）

**先被术语表纠正了一次。** 我原先把页锚点实现成"当次排版的哈希"（`P1-{sha1(本题名单)[:4]}`）。动手做回写时重读 `CONTEXT.md`，发现**「打印批次」这条术语早就写明了**：*"你一次勾选若干错题、生成的一叠重做纸。页锚点指向它，回写时据此知道每页印了哪些题、各占哪几格。"* 而排版会随复习进度变化（毕业、脱离冷却、新录入都会改变分页），所以按当前排版现算的锚点会让**上周打印的那张纸指向另一批题**。改成：生成活页纸 = 落一个 `data/batches/<id>.json` 批次快照，页锚点印成 `3F2A-P1`。这是术语表起作用的一次记录——不用重新面谈，读词表就发现实现跑偏了。

**状态机收成唯一实现时，补掉了四个缺陷**（旧版 `apply_attempt` 是给已停用的拍照判定写的）：

1. **有个隐藏输入**：它只认"现在"，于是无法记录"这次重做其实是三天前在纸上做的"。加了 `at`，标记页上是一个日期框。
2. **冷却起算漏了一种情况**：旧代码在"从未重做过的题"上**跳过冷却检查**，让新录入当天重做就能计入掌握。`CONTEXT`「默认打印清单」写的是"从未重做过的题以录入时间起算"。这是真错，不是风格问题。
3. **通道写死成 `paper`**。
4. **错因是单个字符串**，与卡片上的列表字段不一致；更糟的是把字符串直接 `list()` 会拆成一个个字（`['概','念',…]`）——已按单元素列表处理，并进了验收。

**顺带修掉一个静默的排序错**：打印清单按"上次重做的先后从早到晚"排，用的是**原始时间字符串比较**，而卡里的 `created_at` 是 `+08:00`、重做时刻是 UTC——`06:31Z` 会被排到 `09:00Z` 后面。改为归一到 UTC 再比。

**端到端跑通后，手填字段又暴露两个错**：给"当天"做重做、录入却在下午，读数会显示**"距上次重做 -1 天"**（按当地正午折算后早于录入时刻）；以及**未来日期可以被写进去**，凭空制造一段冷却。前者夹到 0，后者返回 400 并说明原因。

**验收**：`proto/test_mastery.py` 用假时钟钉住 12 条（当天判对不计入、判错永远清零、看清两不相干、冷却天数读数、错因不被拆字）；端到端用一张**临时题卡**走完 批次 → 页锚点 → 回写 → 索引 全链，测完即删——真实的两个题卡 `attempts` 仍是 0。界面的 `--selftest` 也扩到了标记页，并新增一条不变量：**页锚点指不回来时必须明确失败**，绝不能悄悄落到别的题上。

**做成之后确认的一条规则**（不是新决定，是给旧定义补上理由）：按 `CONTEXT`「冷却」的字面，一道题**刚被判错也会进入 7 天冷却**，于是它会立刻回池、同时从默认打印清单里消失一周。这个组合看起来像 bug，我问过一次，结论是保持现状——刚做错、刚重做过的题不该天天再印，想印就勾「显示冷却中的题」。理由已写进术语本身，免得将来被"顺手修掉"。

### 第十轮：把脏数据清掉，并把体检做成可重跑的东西

**这一轮补的是第八轮留下的口子。** `card_warnings` 确实把污染在列表页喊出来了（对 `ef7c47` 报 4 处、对 `41c86b` 报 0 处），但**没有人清**：那张解答题仍然带着选择题的标准答案 `A`，而且已经进了索引、也进了打印批次 `b-20261004-b66e`。闸门只做到"喊"，没做到"清"与"再查"。

**为什么体检必须跑在落盘数据上。** 起点是一次对不上的账：日志说 `1-0000.png` 的转录「完整，连 √42 ≈ 6.48 都在」（对的，那是 `runs/` 里那次调用），而盘上的卡写着另一道题的题干。核对 `runs/` 的九次抽取后确认：对 `1-0000.png` 的三次（14:18、14:20、14:30）全都吐出隧道题干，**没有任何一次吐出过那个 ∃ 题干**——污染只能来自界面。**验收是对调用记录打的分，题卡却能被后来的路径改坏**，中间隔着几十分钟，谁都没发现。所以新增的 `--audit` 只读磁盘、只看落盘数据、随时可重跑：

- 卡片自检（复用 `card_warnings`，规则只留一份）
- 资产指向的文件是否还在：题面裁剪图、擦除图、**整页原图**（它是最后的底）
- **题干转录逐字相同**——这次事故的指纹。`card_warnings` 抓得住「解答题却带着选项答案」，抓不住「题干写的是另一道题」，因为那要对着图看；而"两张卡题干逐字相同"不需要看图，且没有例外
- 索引与卡片是否一致；打印批次引用的题是否还在、版面格是否自洽
- 掌握状态与重做历史是否自洽

**清数据那一半：`--repair <pid>`。** 它对着**整页原图**重抽一次，只修三个「可能来自另一道题」的字段（题干、标准答案、原答），并且先印出对照让你确认它认的是不是同一道题（题型、裁框各是多少）。不做整卡重跑，是因为卡上其余部分（擦除掩膜、版面格、重做历史、考点错因）是人动过的——整卡重跑等于以「修数据」为名的第二次破坏。修复后**退回未审核**：被改的正是「审核」覆盖的字段，它需要人再看一眼（卡里记 `review.reopened_because`，修复过程记 `provenance.repairs[]`，含 before/after）。

**修复的证据链**（不是"看起来对了"）：重抽出的题干与 `runs/` 里三次独立抽取一致（隧道题、含 √42 提示）；重抽出的原答是「(1) 0<x≤80；(2) 未给出最终答案（只写到 y=60x−1200x/(140−x) 就中断了）」，与第八轮人工记下的学生错法（`k=1200`、(0,80]、第 (2) 问停笔）独立吻合。人动过的部分（考点、错因、版面格 `cells=1`、掩膜 4 框、0 次重做）一个没动。

**顺带抓到的一个真 bug：写入服务从不加载密钥。** `load_env()` 只在 `slice.py` 的入口被调用，而 `server.py` 自己也会调模型（「重新定位手写」按钮）——密钥在 `.env.local` / `~/.env.local` 里时，那个按钮在任何机器上都是死的。已修。

**体检自己的一条纪律**：第一版把「解答题的标准答案为空」也报成问题，但那是**按设计如此**（解答题不机判）。把按设计如此的事报成问题，会训练人忽略体检——那比漏报更糟。已降为提示。清完只剩一条真问题：`ef7c47` 的考点为空，那是人的判断，工具不替他填。

**新命令**：`python3 proto/server.py --audit`（只读体检，可重跑）· `--repair <pid> [--apply]`（对着整页原图定点修复）· `--rebuild-index`。界面自检 `--selftest` 不受影响，仍通过。
