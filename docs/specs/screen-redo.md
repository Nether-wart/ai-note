# 屏幕重做（含自动判定接入）

> **标签**：`ready-for-agent`
> **发布**：issue tracker 未配置（`/setup-matt-pocock-skills` 未运行），本文件即 spec 本体。

## Problem Statement

纸上重做那条通道已经端到端建好了：录入 → 审核（含手写掩膜）→ 打印批次 → 活页纸与页锚点 → 扫一次在一屏里标记 → 判定回写 → 掌握与冷却。**而两道题卡的重做次数都是 0——这个循环一次都没有真的转过。**

原因不在实现，在成本。走一次纸上重做要：等凑够题、打印、裁纸、打孔、坐下来写、扫页锚点、在标记页逐题给出判定。而一道**选择题**的第二次重做，实际内容只是敲一个字母。掌握的定义是"连续 2 次判对、且两次之间至少隔 7 天"，也就是每道题至少要排队 7 天、至少走两次这条重通道。结果是可以预见的：题录进来了、纸也印得出来，但第二次重做永远排不上队。

同时，术语表里的「自动判定」定义了另一条通道——*"由系统把敲进去的答案与标准答案做等价比对得出的判定，只适用于答案形式可机判的题型，且只发生在屏幕重做"*——而验收考卷 32/32 全对的判定角色模型正闲置着。**两条通道里，只有一条存在。**

## Solution

打开浏览器就能做重做。选择题敲一个字母、填空题敲一个结果，系统立刻告诉你对／错／看不清，并把它记进这道题的重做历史，冷却与掌握照常推进。不打印、不裁纸、不扫码。

屏幕上看到的题面是**擦除手写后的原题照片**——与重做纸同一份素材，所以屏幕上也不会把答案摆在你面前。判错时顺手记一个错因；机器判错了你可以当场改判。做完一题自动到下一题，直到这一批做完。

解答题与过程题不出现在屏幕重做的作答里：题型决定这道题能否走自动判定，而过程题只能人工确认——它仍然走纸上那条通道。

## User Stories

1. 作为错题本的主人，我希望不打印任何纸就能重做一道题，这样我不必为了一个字母的作答去裁纸、打孔、扫码。
2. 作为做重做的我，我希望打开一个网址就直接开始，这样「想重做」和「正在重做」之间只隔一次点击。
3. 作为做重做的我，我希望屏幕上看到的是擦除手写后的原题照片，这样我的答案不会被自己的订正或错解提前泄露。
4. 作为做重做的我，我希望选择题只敲一个字母，这样一次重做只花我几秒。
5. 作为做重做的我，我希望填空题只要敲一个结果（分数、根式、区间、集合都可以），这样我不必迁就系统的输入格式。
6. 作为做重做的我，我希望系统按数学等价判断而不是逐字比较，这样 `2/√3` 不会被判成错。
7. 作为做重做的我，我希望提交后立刻看到对／错／看不清，这样我不必等下一次打印才知道进度。
8. 作为做重做的我，我希望判对时看到「已计入 1/2」这类读数，这样我知道这道题离毕业还差多远。
9. 作为做重做的我，我希望判对但仍在冷却期时被告知「只热身、不计入掌握」，这样我不会误以为进度在推进。
10. 作为做重做的我，我希望判错时立刻看到「清零回池」，这样我知道这道题重新开始计数。
11. 作为做重做的我，我希望判错时被提示记一个错因，这样我的错因历史里不会出现空洞。
12. 作为做重做的我，我希望系统没把握时说「看不清」而不是猜一个「对」，这样一道题不会因为我蒙对而白拿一次掌握计数。
13. 作为做重做的我，我希望低置信度的判定被明确标出置信度，这样我知道该不该信它。
14. 作为做重做的我，我希望模型答非所问或调用失败时，那一次重做**不留下任何记录**，这样我的重做历史里不会有凭空出现的条目。
15. 作为做重做的我，我希望模型失败时看到明确的错误提示并可以直接重试，这样网络问题不会变成脏数据。
16. 作为做重做的我，我希望可以当场改判（机器判错了就改成我看的），这样机器的一次误判不会永久留在我的历史里。
17. 作为做重做的我，我希望改判之后仍能看出原本的判定是什么、是谁改的，这样将来回顾时不会以为它一直是人对的。
18. 作为做重做的我，我希望一次连续做完一批题（做完自动到下一题），这样我不会被列表与跳转打断。
19. 作为做重做的我，我希望这一批的顺序是「最久没做的排最前」，这样我用的优先级和纸上那条通道完全一致。
20. 作为做重做的我，我希望可以勾「显示冷却中的题」先把刚录入的题做掉，这样刚错的题当天就能再来一次（照常记录、不推进掌握）。
21. 作为做重做的我，我希望正在做的这一批在判完之后不会突然换掉，这样我做到第 3 题时不会发现队列已经变了。
22. 作为做重做的我，我希望页面明确告诉我「还有 N 道题不能自动判定、只能纸上重做」，这样清单里少了几道题看起来不像 bug。
23. 作为错题本的主人，我希望解答题不出现作答框，因为过程题只能人工确认，屏幕上敲不出过程。
24. 作为错题本的主人，我希望未审核的题不参与自动判定，因为它的标准答案还不可信。
25. 作为错题本的主人，我希望没有标准答案的题被明确拒绝并说明原因，而不是给我一个编出来的判定。
26. 作为错题本的主人，我希望在清单页就能看出每道题能走哪条通道，这样「题型决定可机判」这条规则是可见的。
27. 作为错题本的主人，我希望屏幕重做与纸上重做写进同一份重做历史，这样我不必记住某次重做走的是哪条通道。
28. 作为错题本的主人，我希望每次自动判定都记下是哪个模型、当时有多确定，这样我日后能回答「这条判定是谁给的」。
29. 作为错题本的主人，我希望每次自动判定都在 `runs/` 留档，这样重跑验收时拿得出证据。
30. 作为错题本的主人，我希望判定回写后索引立刻更新，这样清单页与重做历史马上一致。
31. 作为错题本的主人，我希望换判定模型必须重跑考卷，这样「验收过的模型」这句话始终为真。
32. 作为维护这套工具的我，我希望「能不能自动判定」的判断只有一份实现，这样界面与命令行不会各判各的。
33. 作为维护这套工具的我，我希望界面自检里有一条「重做页面不得泄露标准答案与正解」，这样我改界面时不会把答案印在屏幕上。
34. 作为维护这套工具的我，我希望自检能发现「越界」，并且越界时明确失败而不是落到别的题上。
35. 作为维护这套工具的我，我希望端到端测试用临时题卡、测完即删，这样真实的题卡不被测试污染。
36. 作为维护这套工具的我，我希望映射规则（等价／置信度 → 判定）是不联网的纯函数并有边界用例，这样我不花钱就能测规则。
37. 作为单用户，我希望整个过程不需要登录、不需要账号，数据只在我机器上。
38. 作为在意隐私的我，我希望自动判定只把文本（标准答案与作答）发给模型、不发送任何图片，这样屏幕重做不新增任何图像出境。

## Implementation Decisions

**一个写入口，服务自己决定判定。** 屏幕重做的判定回写只经过已有的 `POST /api/attempt/<pid>`，不新开端点。理由是硬的：客户端绝不能自己声称「模型说等价」——第八轮那次事故正是把不该写的字段写进了卡里（第一题的原答与标准答案被写进第二题，而第二题是解答题）。判定由服务自己问模型、自己映射、自己记录来源与置信度；客户端只能提交「我答的是什么」和「人对这次判定的修正」。

同一个端点收三种形态的请求：

- **自动判定**（屏幕重做）：`{channel: "screen", answer: "<作答文本>"}` → 服务判断能否自动判定 → 问判定角色 → 映射 → 记录。
- **人工确认**（纸上重做沿用，行为不变）：`{channel: "paper", verdict, at, error_causes}`。
- **定点修正**：`{attempt_at: "<那一次重做的时刻>", error_causes?, verdict?}` → 只改那一次重做的错因与判定，用于补记错因与改判。用 `attempt_at` 定位而不是「最近一次」，因为两次提交之间「最近一次」会漂移。

**能不能自动判定：一处实现，三个拒绝理由。** 题型为解答题（过程题只能人工确认）、标准答案为空（没有判定的基准）、尚未审核（未审核的标准答案还不可信）。三者都返回 400 加一句明确文案，界面照原话显示。这条判断必须只有一份——现已停用的命令行判定里已经有前两条，新端点与它共用，避免两处各判各的。

**判定角色的调用形状。** 输入是纯文本：标准答案与这次作答，**不发送任何图片**（等价性判断不需要看题；这也意味着屏幕重做不新增任何图像出境）。输出沿用已有的等价性判定约定：

```
{"equivalent": bool, "confidence": 0..1, "reason": "一句话"}
```

**映射成判定（纯函数，一处实现）。**

| 模型的回答 | 判定 |
|---|---|
| 置信度 < 阈值 | 看不清 |
| 置信度 ≥ 阈值，且等价 | 对 |
| 置信度 ≥ 阈值，且不等价 | 错 |
| 输出残缺／不可解析／`equivalent` 不是布尔 | 看不清 |
| 调用失败（网络／超时／缺密钥） | **不记录任何重做**，返回错误让人重试 |

阈值是一个模块常量（初值 0.9，可用验收调整）。它的高低不对称：假「错」只浪费一点时间，假「对」会让一道题白拿一次掌握计数、甚至悄悄毕业、从默认打印清单里消失。所以阈值宁可高——往高调最多多几次人工确认，往低调则制造这套设计唯一禁止的错。

**模型失败不等于看不清。** 模型说「看不清」是一次判定（要记录、要进历史、对掌握两不相干）；「我们没能问成」不是判定。把后者记成看不清，会在重做历史里造出一条没发生过的重做，并静默推进「上次重做」时刻，于是冷却被凭空重置。

**题面载体与重做纸同源。** 屏幕上做题时显示的必须是**擦除手写后的题面照片**（与重做纸同一份素材）；未擦除的题面图不得出现在重做页面上。理由是同一件事：订正里含正确答案，把它摆在做题的人面前，重做就没有意义了。没有擦除图的题不进屏幕重做。

**这一批题放在 URL 里，不落盘。** 形如 `/redo?queue=<题目列表>&i=<第几题>`。屏幕重做不需要打印批次那种快照——批次存在的唯一理由是「已经打印出去的那张纸要永远指得回同一批题」，屏幕上不存在这个问题。但队列必须由客户端持有并原样传递，因为**判完一道题的瞬间它进了冷却、从默认打印清单里消失了**，服务端现算的第 i+1 题会漂移。第九轮那条教训在这里同样适用：越界必须明确失败，绝不悄悄落到别的题上。

**选取与排序复用既定规则。** 这一批题就是默认打印清单（未毕业且已脱离冷却，按上次重做从早到晚，从未重做的以录入时间起算），「显示冷却中的题」开关语义不变。不发明第二套选题规则。

**不能自动判定的题要说出来。** 页头给出「另有 N 道题不能自动判定（解答题／未审核／无标准答案），只能纸上重做」并列出题号。静默缩短的清单正是这个项目反复被咬的那类失败（题型枚举静默退回默认值、探针不报错地编造、界面拖完框不更新），所以宁可多一行字。

**解答题不给作答框。** 题型决定这道题能否走自动判定，而过程题只能人工确认。屏幕上也不提供「自评对错」——那既不是自动判定，也不是纸上那条有手写证据的通道。

**清单页标出每题的通道。** 每题显示「屏幕可做」或「只能纸上」，因为「题型决定可机判」这条规则必须可见，否则少一道题看起来就像 bug。

**记录形状。** 那一次重做记下通道、来源、置信度，以及判定它的模型；改判后来源变成人给的来源，并在该次重做上保留原判定（`overrode`），从而「这条判定原本是谁给的」永远可查。这些字段让日后的体检能回答：库里有多少判定是机器给的、其中多少是低置信度的。

**留档。** 每次自动判定都往 `runs/` 写一份调用留档（提示词与用量），与抽取、手写定位、擦除探针的既有做法一致。第十轮的教训是：验收是对调用记录打的分，没有留档就没有证据链。

**索引。** 判定回写与定点修正之后照旧重建派生索引。

**界面自检。** `--selftest` 增加重做页面的不变量（见下）。

## Testing Decisions

**好测试的判据**：只测外部行为——「一个作答进去，一个判定与状态机读数出来」。不测模型的措辞、不测提示词文本、不测内部调用顺序。凡是能用构造输入喂的规则，都不要花钱用真模型去测。

**四层，全部沿用现成做法：**

1. **纯逻辑（不联网、不花钱）**：映射表与阈值边界（恰好等于阈值时取哪一侧）、三个拒绝理由、模型失败不落地、定点修正只能改指定那一次重做且只能改判定与错因。
   *prior art*：`proto/test_mastery.py`——假时钟、12 条断言、不联网、只验规则。
2. **界面不变量**：`--selftest` 对重做页面的检查——只引用擦除后的题面图、不得出现标准答案与正解的文本片段、队列为空或越界必须明确失败、作答框与结果区都在、页头有「不能自动判定的 N 道题」。
   *prior art*：现有自检对清单页与标记页的检查（它自己犯过「判据写成 CSS 选择器」的错，所以判据要对着真实 HTML 写）。
   *已知弱点*：选择题的标准答案常是单个字母（`A`），逐字判据抓不住它；这条不变量只能覆盖多字符的标准答案与正解文本，单字母那一条要靠在提交之前不渲染任何判定节点来兜。
3. **模型能力**：沿用现有考卷（三份自出题 + 两份人写固定考卷，经判定角色验收跑）。**提示词不改就不用重跑；改了就必须重跑。**
   *prior art*：`proto/accept --role judge`，来源是验收记录里那 32/32。
4. **端到端**：用一张临时题卡走完 作答 → 判定 → 重做历史 → 冷却读数 → 索引，测完即删。
   *prior art*：第九轮的做法——真实的两张题卡的重做次数至今仍是 0，测试不污染它们。

**不测**：模型判对的具体概率（那是验收的事，不是测试的事）。

## Out of Scope

- **复习纸**：术语已定义、代码里零实现；它服务的是「翻看」而不是「重做」，本 spec 不碰。
- **审核队列按「AI 自身的把握」排序**：现在按上次重做时间排。
- **新标签提案的批准流程**：`new_tag_proposals` 目前只进不出，考点大纲还是种子。
- **配额**（自我保护用的每日上限）。
- **一张照片里多道题的切分**：一次仍只处理一道题。
- **屏幕上的数学输入法／LaTeX 键盘**：作答是纯文本，靠等价性判定吸收写法差异。
- **解答题与证明题的过程判定**：永久排除，只能人工确认。
- **屏幕重做结果的打印或导出**。
- **多用户、登录、配额分摊**：ADR 0003 已排除。

## Further Notes

- **为什么是它**：纸上那条通道已经端到端建好，而两道题卡的重做次数都是 0——循环一次都没转过。掌握要求「连续 2 次判对且间隔 ≥7 天」，如果唯一的通道是裁纸、打孔、写字、扫码、逐题标记，那么每道题的第二次重做永远排不上队。屏幕通道是这条路上门槛最低的一侧：敲一个字母。
- **钱已经花过了**：判定角色的模型已过验收（自出题 15/15 + 人写题 17/17 = 32/32），视觉探针也过。本 spec 不需要新模型、不需要新验收。
- **成本与隐私都在往好的方向**：判定调用是纯文本（标准答案 + 作答，无图），比抽取便宜一个量级；且不发送任何图片，所以屏幕重做不新增任何数据出境的面。
- **唯一不可接受的错是假「对」**：它会白送一次掌握计数，甚至让一道题悄悄毕业、从默认打印清单里消失。阈值、低置信度落向看不清、模型失败不落地——这三条都是为了这一件事。
- **一条纪律**：换判定模型必须重跑考卷，结果记进验收记录。不过考不许上岗。
