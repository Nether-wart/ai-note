# 整页切分与错题筛选

> **标签**：`ready-for-agent`
> **发布**：issue tracker 未配置（`/setup-matt-pocock-skills` 未运行），本文件即 spec 本体。
> **界面形态**：按 [ADR 0006](../adr/0006-docusaurus-base-with-tauri-compatibility.md)，界面是 Docusaurus 站点里的 React 页面；本 spec 只钉**写入服务的契约**（它跨平台形态存活）。

## Problem Statement

录一道错题现在的成本是「一张照片一道题」：抽取一次只处理一道题，还要用命令行说明「照片里是第 12 题」（提示词里写死了「只判这一道题」）。而真实的入口是**一整页试卷**：十几道题印在一张纸上，其中三四道有红笔订正。

于是拍照那一刻就要做判断（逐题对焦），或者拍一整页再人工逐题裁。库里那两张卡都是逐题拍的——**录入摩擦比第一次还大**，而录入摩擦正是这类工具最常见的死因。

数据结构也不支持：题卡 id 直接来自照片哈希（同一张照片＝同一道题，所以"会被覆盖"这件事在代码注释里已经写着）。一页多题在这个前提上根本站不住。

## Solution

拍一整页，机器把它切成题，并且只把**有红笔订正痕迹**的那几道收进库。切错了、收错了、漏了，在一个界面上改：拖边界、合并、拆分、整块丢弃、改题型，确认后入库。

没有红笔痕迹的题**不当场丢掉**，而是明确列出来（「这一页还有 4 道没有红笔痕迹，未入库」），要收一键补收。这条规则由代价的不对称决定：漏收一道错题，它永远不在库里；误收一道对题，审核时删掉，几秒。

## User Stories

1. 作为录入的人，我希望拍一整页就完成录入，这样我不必在拍照时逐题对焦。
2. 作为录入的人，我希望机器告诉我这一页切出了几道题、分别在哪，这样我一眼能看出漏没漏。
3. 作为录入的人，我希望它自动只收有红笔订正痕迹的题，这样我不必从十几道里挑出那三道。
4. 作为录入的人，我希望没有红笔痕迹的题被明确列出来而不是消失，这样我知道「少了几道」是筛选的结果、不是 bug。
5. 作为录入的人，我希望可以一键把那几道也收进来，这样筛选判错时我有补救。
6. 作为录入的人，我希望看到切分框画在原图上，这样我能判断框对不对。
7. 作为录入的人，我希望可以拖动框的边界，这样切歪了不必重拍。
8. 作为录入的人，我希望可以合并两个框（一道题被切成了两半）。
9. 作为录入的人，我希望可以把一个框拆成两个（两道题被并成了一块）。
10. 作为录入的人，我希望可以整块丢弃（这不是一道题，是页眉、页码或草稿）。
11. 作为录入的人，我希望可以改题型，这样模型判错的题型不必等到审核时再修。
12. 作为录入的人，我希望机器在「题号不连续」时报警（缺 18 题），这样漏题会响，而不是安静地少一张卡。
13. 作为录入的人，我希望机器在「两个框重叠」或「有墨迹没被任何框覆盖」时报警，同样的理由。
14. 作为录入的人，我希望同一页重复抽取时先给我对照（新增／替换／保留），这样我不会把上一次修好的卡片冲掉。
15. 作为录入的人，我希望红笔勾（表示做对）不被当成「这道题错了」，这样库里不会混进一堆做对的题。
16. 作为录入的人，我希望分不清红笔是勾还是订正时落向「收」，这样我不会因为机器的犹豫丢掉一道错题。
17. 作为录入的人，我希望入库后直接进审核队列，这样录入与审核是一条流而不是两件事。
18. 作为录入的人，我希望手机拍完就能传（经局域网／Tailscale），这样录入不需要先把照片弄到电脑上。
19. 作为录入的人，我希望录入时可以注明「这一页是第几页／来自哪张卷子」，这样同一张卷子的上下文不丢。
20. 作为审核的我，我希望同一页的几道题能一起看，这样审起来有上下文。
21. 作为审核的我，我希望一页多题带来的串题风险被专门检查（题干逐字相同、解答题带着选项答案），这样第八轮那次污染不会重演。
22. 作为审核的我，我希望一页里哪些题来自同一页是可查的，这样我发现一页切错时能整页重来。
23. 作为维护这套工具的我，我希望「页」是一等实体（一页一文件），这样切分结果、收入决策、生成的题卡三者可以被审计。
24. 作为维护这套工具的我，我希望红笔检测复用已有的颜色掩膜而不是新写一套，这样「实测可靠」这句话继续成立。
25. 作为维护这套工具的我，我希望「有红笔痕迹」的判据阈值只有一份实现，这样裁剪体检与错题筛选不会各判各的。
26. 作为维护这套工具的我，我希望切分与语义的模型调用留档到 `runs/`，这样改提示词之后能对账。
27. 作为维护这套工具的我，我希望改切分提示词必须重跑抽取验收，这样「验收过的模型」不被绕过。
28. 作为维护这套工具的我，我希望题卡 id 与页面哈希解耦，这样同一页多道题不会互撞。
29. 作为维护这套工具的我，我希望存量数据（一页一题的旧卡）能被审计接受并回填成页文件，而不是被当成错误。
30. 作为单用户的我，我希望整个过程不需要登录，数据只在我机器上。

## Implementation Decisions

**「页」成为一等实体：一页一文件。** 页文件持有：整页照片、切分块列表（每块的边界、红笔统计、收入或丢弃、以及它生成出的题卡 id）、以及来源信息（第几页、哪张卷子）。理由是可审计与可重来：切分结果与收入决策一旦只存在于界面的内存里，「漏了一题」就永远查不出来，而静默丢题是这个项目最怕的一类失败。切分块与题卡之间是**绑定关系**，记在页文件里——这同时解决了命名问题。

**题卡 id 与页面哈希解耦。** 现行 id 是「照片哈希」的函数，一页多题必然互撞。新规则：id 在**首次入库时分配**并写回页文件；重切时按位置重合度与已有绑定匹配，**保留原有绑定**，只有真正新增的块才分配新 id。所以重切不会把已审核、已重做过的卡片改名。

**模型出候选块，确定性统计做对账。** 切分本身必须有模型参与：学生的手写解答会填满题与题之间的空隙，纯几何投影（按行统计墨迹空隙）在真实卷子上会散架——这一点在裁剪体检里已经写明（「黑笔手写与印刷体在灰度上同色，机器分不开」）。对账则必须是确定性的，这是把「静默丢题」变成响声的唯一办法：

- **题号连续性**：模型报出每块的题号；缺号（有 17、19 没有 18）直接报警。这是最便宜也最强的一条。
- **块之间不重叠**：同页两块的边界不相交。
- **覆盖率**：该页的墨迹（排除整页草稿式手写之后）应被各块基本覆盖；大片未被覆盖的墨迹要报出来。

**红笔痕迹哪来的：复用已有的颜色掩膜。** 饱和度阈值 → 彩笔掩膜、按框统计像素数，这套零件已经在用（裁剪体检里那句「框内有彩笔手写 Npx——订正常常是红笔」）。它在实测里已被证明可靠（彩笔擦除后残留为 0），所以不需要新发明。**但要收成一份实现**：现在那个阈值是写在体检里的一处字面量，筛选与体检必须共用同一个具名常量，否则两处会各判各的。

**红笔痕迹 ≠ 这道题错了。** 红笔还可能是对勾、圈题号、打分数。所以分两层：统计只回答「这一块有没有红笔、多少」，**语义由模型回答「这点红笔是勾、是圈、是订正，还是只是分数」**。收不收的规则：

- 有表示「错」的痕迹（叉、圈错、改错、订正）→ 收。
- 有红笔但只是对勾 → 不收。
- **判不准 → 收**（代价不对称，见上）。

**重跑同一页必须走对账，不许整页静默覆盖。** 这个项目已经出过一次「同一张照片重跑抽取会静默覆盖上一次的题卡」的事故。重切返回的必须是逐块的对照：新增／替换／保留，以及「这一块对应的卡片已经审核过或已有重做历史」的警告。人动过的卡片（审核过的字段、掩膜、重做历史）不允许被一次重切抹掉——这与定点修复那条决定的理由完全一致（**不做整卡重跑，因为卡上其余部分是人动过的**）。

**手动修正的最小集合**：拖边界、合并两块、拆分一块、整块丢弃、切换收入／丢弃、改题型、改题号。不做：旋转校正、透视矫正、双栏自动分区（见「超出范围」）。

**写入服务的契约（一个接缝：页资源）。** 四个动作，全部经过写入服务（ADR 0001）：

1. **建**：照片进来 → 存图、建页文件、跑切分 → 返回块列表（含每块的红笔统计与建议去留）。
2. **改**：按当前块列表改写页文件（边界、合并、拆分、去留、题型、题号）并重算统计。
3. **重切**：对已有页重跑切分 → 返回逐块对照（新增／替换／保留），**不写题卡**。
4. **入库**：按当前块列表生成题卡（每块一个），并回写绑定；已经生成过的块不重复生成。

四个动作合起来是**一个**接缝——界面的所有读写都落在这个页资源上，模型调用与图像统计都在服务内部，界面不碰照片处理。

**存量数据要能进来。** 现有的两张卡是「一页一题」，没有页文件。审计把「卡片缺少页绑定」报为提示而不是错误，并提供一个从卡片反推页文件的回填（照片 + 单个块 = 那张卡的边界）。旧数据不该因为新结构而变成脏数据。

**入库后进审核队列**，不另开一条流。新卡片一律未审核，于是照既有规则：不参与自动判定、不进重做纸。

## Testing Decisions

**好测试的判据**：只测外部行为——「一页照片进去，一组块与一组卡片出来」，以及「一份块列表进去，一条明确的对账结论出来」。不测模型措辞、不测内部调用顺序。

**四层：**

1. **纯逻辑（不联网、不画图）**：题号连续性、块重叠、覆盖率、去留决策（痕迹类型 → 收／不收／待定，含「判不准落向收」）、id 绑定在重切时的稳定性（同一块重切后仍是同一个 id）。用构造的块列表喂进去即可。
   *prior art*：`proto/test_mastery.py`——构造输入、不联网、只验规则。
2. **确定性统计（不联网，用合成图）**：用 PIL 画一页假卷（白底 + 几段印刷体墨迹 + 一个红笔块 + 一个黑笔块），断言块级红笔统计能区分这两块，以及阈值常量在两处（体检与筛选）行为一致。
   *prior art*：`proto/cropcheck`——它的判据就是「框内彩笔像素数」，同一套算法。
3. **真图回归**：现有那两张真实照片各是「一页一题」，切分必须仍然切出一道、且题型与边界与现存卡片一致。这是防止「新功能把已验证的东西弄坏」的那一层。
4. **模型能力**：切分与红笔语义都走抽取角色，所以**改提示词就必须重跑抽取验收**（那张「真实照片上的直接可用率」的考卷）。
   *prior art*：`proto/accept --role extract`。
5. **端到端**：合成一页 → 切分 → 收两道丢一道 → 生成两张卡 → 索引 → 审计无报错；再对同一页重切一次，断言已入库的块变成「保留」而不是「替换」。测完即删（沿用第九轮的做法）。

**已知弱点（必须写下来，免得被当成保证）**：题号连续性依赖模型报出的题号；如果模型把题号也报错了，这条最强的检查会失灵。所以真图回归那一层和人工确认都不能省——**检查能抓住的，永远只是它判据覆盖的那一部分**。

## Out of Scope

- **双栏／多栏版式**：先只假设单栏竖排。遇到双栏时靠人工修正兜。
- **从 PDF 直接切**：只处理照片。
- **自动判断「这道题你做错了」**：只用红笔痕迹这一条规则，不用 AI 去猜对错。
- **跨页的题**：一道题印到下一页的情形不管。
- **旋转与透视校正**：拍歪了请重拍或人工拖框。
- **一次拍多页**：一次一页。
- **屏幕重做**：另一份 spec。
- **复习纸**：仍无实现，不在本 spec。

## Further Notes

- **这条标准的已知漏法**（写在前面，免得日后当成 bug 查）：老师只写分数不写订正；学生用蓝笔或黑笔订正；红笔勾表示做对；整张卷子本身就是红笔印刷的。前三种会**漏收**，第四种会**误收**——所以补收入口和「列出未入库的题」不是可选装饰，它们是这条规则的必需品。
- **复用清单**：颜色掩膜与按框像素统计（红笔检测）、裁剪体检的条带统计与判据写法（对账）、抽取校验器（块级字段校验）、卡片自检与定点修复（串题检查与重切对账）。一页多题时「两张卡题干逐字相同」这条**没有例外**的检查变得更关键：相邻题互相污染的概率随同页题数上升。
- **与 ADR 0005 的关系**：红笔既是要**擦掉**的东西（泄露答案，必须擦净），也是「**这题错了**」的证据（筛选）。同一份颜色掩膜服务两个目的，一个是保密，一个是筛选。这不是巧合，是同一件事实的两个用途。
- **顺序建议**：本 spec 与「屏幕重做」互不依赖，但都依赖 ADR 0006 定的界面形态。若要先出界面，先做屏幕重做（它不需要新数据结构）；本 spec 会引入页文件这一新实体，改动面更大，适合放在数据结构稳定之后。
